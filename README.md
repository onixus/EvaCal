# EvaCal — калькулятор трудозатрат и генератор документации ГОСТ 34

Веб-приложение для расчёта трудозатрат в человеко-часах по этапам проекта, автоматической
постановки задач согласования на заказчика и генерации комплекта нормативной документации по **ГОСТ 34** с рамками **ГОСТ 2.104-2006**.

## Стек

- Next.js 15 (App Router) + TypeScript
- Prisma + SQLite (лёгкая встроенная БД, файл `prisma/dev.db`)
- Tailwind CSS (темная тема Nord + высококонтрастный интерфейс)
- docx, mammoth, jszip, pdfkit, sheetjs (XLSX)
- Docker & Docker Compose + GitHub Actions CI/CD (GHCR)

---

## Генератор документации ГОСТ 34 (ГОСТ 34.602-89, РД 50-34.698-90)

В систему встроен **Конструктор-Студия документов ГОСТ 34**, позволяющий выгружать как отдельные нормативные документы, так и весь комплект в виде единого ZIP-архива.

### Комплект выгружаемых документов:

1. **ТЗ** — _Техническое задание (ГОСТ 34.602-89)_: Разделы 1..8, включая состав подсистем, показатели качества и матрицу прослеживаемости.
2. **ПЗ** — _Пояснительная записка (РД 50-34.698-90 п.2.1)_: Архитектурное обоснование, структура ПО, СУБД и системные требования.
3. **АФ** — _Описание функций (РД 50-34.698-90 п.2.2)_: Детальное описание автоматизируемых функций, пользовательских ролей и сценариев.
4. **ПМИ** — _Программа и методика испытаний (РД 50-34.698-90 п.2.7)_: Методика приемо-сдаточных испытаний, проверочные тесты и сценарии.
5. **SPEC** — _Спецификация оборудования и ПО (ГОСТ 34.201-89)_: Перечень серверного оборудования, ОС, СУБД и спецификация АРМ.

### Рамки и штампы ГОСТ 2.104-2006:

- **Лист 1**: Форма 2 (основная надпись высотой 40 мм с подписями: _Разработал, Проверил, Н.контр., Утвердил, Утвердил от Заказчика_).
- **Листы 2+**: Форма 2а (малый штамп высотой 12 мм).
- **Поля документа**: Левое 20 мм, Правое 10 мм, Верхнее 15 мм, Нижнее 45 мм (гарантирует отсутствие наложения текста на штампы).

## Серверный парсер и нормализация вендорских ТЗ

1. **Серверный извлекатель документов (`mammoth`)**:
   - Загрузка файлов `.docx`, `.txt`, `.md`, `.json` без искажений кодировки и без срезки длинных наименований требований.
2. **Очистка от технического мусора (Sanitizer)**:
   - Автоматическое удаление непечатаемых бинарных символов, нулевых пробелов, буллетов (`•`, `—`, `*`), номеров страниц и колонтитулов.
3. **Локальный ИИ-модуль нормализации (Ollama / LM Studio)**:
   - Провайдеры настраиваются **на сервере** (`OLLAMA_HOST`, `LMSTUDIO_HOST`, `EVACAL_LLM_PROVIDERS` — см. `.env.example`). В панели `⚙️ Настройки ИИ` пользователь выбирает провайдера из списка; адреса и ключи доступа в браузер не передаются и из браузера не принимаются.
   - Встроенные провайдеры: **Ollama** (`http://localhost:11434`) и **LM Studio / OpenAI-compatible** (`http://localhost:1234/v1`).
   - Авто-определение локальных моделей (`qwen2.5`, `llama3.2`, `mistral`, `deepseek-r1`) для перефразирования исходного текста в формулировки ГОСТ 34.
   - Умный фоллбек: если ИИ-сервер недоступен, автоматически применяется регекс-нормализатор.
   - Роуты `/api/gost34/*` (ИИ, загрузка вендорских файлов, генерация документа из произвольных данных) требуют входа в роли `architect` или `admin`. Экспорт готового расчёта остаётся открытым, как PDF/XLSX/JSON.

## Бизнес-логика калькулятора

- Каждый шаблон опросника (админ) описывает вопросы и формулы этапов:
  `часы = базовые_часы + часы_на_единицу × значение_числового_поля`.
- При заполнении опросника пресейлом создаётся расчёт: этапы генерируются из формул шаблона
  и выстраиваются в календарный план.
- Для каждого этапа, где исполнитель — **консультант, разработчик, инженер или аналитик**,
  автоматически добавляется задача согласования на заказчика (**3 рабочих дня** по умолчанию).
- Для каждого расчёта в трудозатраты добавляется **РП**: 16 ч на старт/закрытие + **10% / 20% / 30%** от трудозатрат остального проекта.

## Доступ (RBAC)

- **Пресейл** и **архив расчётов** (`/`, `/calculations/[id]`) открыты без входа.
- **Архитектор** (`/architect`) и **администратор** (`/admin`) требуют входа под своей ролью.
- При первом запуске (`npm run db:seed`) генерируются случайные пароли в `credentials.local.txt`.

## Запуск

### Локальный запуск (Node.js)

```bash
cp .env.example .env
npm install
npm run db:push     # создаёт SQLite-схему
npm run db:seed     # демо-шаблон, расчёт и пароли architect/admin
npm run dev
```

### Форматирование и линт

- `npm run format` — автоматически отформатирует код с помощью Prettier.
- `npm run lint` — проверит код линтером ESLint.
- `npm run prepare` — выполнит `format` и `lint` последовательно (используется в CI).
- `npm audit` — проверяет уязвимости; после обновления `nanoid` запустите `npm install` для применения исправления.

Хук `pre-commit` от Husky автоматически запускает `npm run format && npm run lint` перед каждым коммитом.

Приложение будет доступно на `http://localhost:3000`.

---

### Docker & Docker Compose

```bash
cp .env.example .env   # задать SESSION_SECRET
docker compose run --rm migrate   # миграция схемы и создание демо-данных
docker compose up -d --build
```

### GitHub Actions CI/CD и Docker Registry (GHCR)

В репозиторий встроен пайплайн `.github/workflows/docker-publish.yml`.
При пуше в `main` или создании релизов Docker-образ автоматический собирается и публикуется в **GitHub Container Registry**:

```bash
docker pull ghcr.io/onixus/evacal:latest
```
