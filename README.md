# EvaCal — калькулятор трудозатрат

Веб-приложение для расчёта трудозатрат в человеко-часах по этапам проекта, с автоматической
постановкой задач согласования на заказчика.

## Стек

- Next.js 14 (App Router) + TypeScript
- Prisma + SQLite (лёгкая встроенная БД, файл `prisma/dev.db`)
- Tailwind CSS

## Бизнес-логика

- Каждый шаблон опросника (админ) описывает вопросы и формулы этапов:
  `часы = базовые_часы + часы_на_единицу × значение_числового_поля`.
- При заполнении опросника пресейлом создаётся расчёт: этапы генерируются из формул шаблона
  и выстраиваются в календарный план. Рабочий день начинается в 9:00, его длительность
  (4–6 ч) и учёт выходных задаются администратором **на уровне шаблона** (см. ниже).
- Для каждого этапа, где исполнитель — **консультант, разработчик, инженер или аналитик**,
  автоматически добавляется задача согласования на заказчика (по умолчанию **3 рабочих дня**),
  которая блокирует начало следующего этапа. Архитектор может задать свою длительность
  согласования для каждого такого этапа отдельно.
- Архитектор может пометить любой этап как **параллельный**: он стартует одновременно с
  предыдущим (не параллельным) этапом, а не после его завершения. Следующий обычный этап
  всё равно ждёт, пока закончатся все этапы и согласования внутри параллельной группы.
- В итоговые трудозатраты каждого расчёта автоматически добавляется **РП** (руководитель
  проекта): 16 ч на старт и закрытие проекта + **10% / 20% / 30%** от суммарных трудозатрат
  остальных этапов — в зависимости от значения вопроса с типом «Сложность проекта» (Простой /
  Средний / Сложный; 20% по умолчанию, если такой вопрос в шаблоне не задан). **РП не отображается
  как отдельный этап на Ганте** — только в сводке трудозатрат.
- Архитектор может редактировать и добавлять этапы, а также фиксировать **риски**: описание +
  дополнительные часы, которые прибавляются к итоговым трудозатратам (риски тоже не появляются
  на Ганте — только в сводке). После любых правок график и задачи согласования пересчитываются
  заново, а затем архитектор утверждает расчёт пресейла.
- Все расчёты (включая утверждённые и старые) доступны всем — без ограничений доступа.

### Дата старта проекта и «Требования и ограничения»

- Весь Гантт считается от **даты старта проекта** расчёта — даты начала/окончания отдельных
  этапов не задаются вручную, они всегда выводятся из даты старта и трудозатрат.
- Дату старта можно зафиксировать на уровне шаблона (админ, `/admin/[id]`): если задана в
  шаблоне — она обязательна для всех расчётов по этому шаблону, и пресейл не может её изменить.
  Если не задана — пресейл сам вводит дату при создании/редактировании расчёта, а после
  утверждения архитектором она фиксируется вместе со всем расчётом.
- Архитектор может менять дату старта в любой момент до утверждения — даже если она зафиксирована
  шаблоном. Изменение сдвигает весь график, сохраняя текущие трудозатраты этапов.
- **«Требования и ограничения» — это поле на уровне каждого этапа**, а не всего проекта.
  Заполняется и редактируется архитектором вместе с названием/ролью/часами этапа.

### Рабочий график шаблона

В `/admin/[id]` администратор задаёт для шаблона:
- **длительность рабочего дня** — от 4 до 6 часов (значение вне диапазона обрезается сервером),
  день всегда начинается в 9:00;
- **учитывать ли выходные** — если включено, суббота и воскресенье считаются рабочими днями
  наравне с буднями.

Настройки применяются при любом пересчёте графика (создание расчёта, правки пресейла или
архитектора, включая параллельные этапы и кастомные сроки согласования).

## Доступ (RBAC)

- **Пресейл** и **архив расчётов** (`/`, `/calculations/[id]`) открыты без входа.
- **Архитектор** (`/architect`) и **администратор** (`/admin`) требуют входа под своей ролью.
- При первом запуске (`npm run db:seed`) для ролей `architect` и `admin` генерируются случайные
  пароли. Они **один раз** выводятся в консоль и сохраняются в `credentials.local.txt`
  (в `.gitignore`, не попадает в репозиторий) — после входа смените пароль в `/account` и удалите файл.
- Роль присвоена жёстко: логин `architect` → роль «архитектор», логин `admin` → роль «админ».
  Смешивание ролей (например, доступ архитектора в `/admin`) запрещено на уровне API и страниц.
- Администратор может создавать новые учётные записи (роль «архитектор» или «админ») в
  `/admin/users`: логин + роль, пароль генерируется автоматически и показывается один раз сразу
  после создания. Удалить последнего администратора нельзя.

## Три интерфейса

- **`/presale`** — заполнение опросника, просмотр этапов, трудозатрат и диаграммы Ганта,
  отправка на согласование архитектору.
- **`/architect`** — просмотр расчётов на согласовании, редактирование/добавление этапов,
  утверждение расчёта.
- **`/admin`** — визуальный конструктор форм: вопросы опросника и формулы этапов.
- **`/`** и **`/calculations/[id]`** — архив всех расчётов, доступный всем.

## Экспорт: PDF, XLSX, JSON

На странице любого расчёта (архив, пресейл, архитектор) есть кнопки **PDF / XLSX / JSON** —
все три отдают один и тот же набор данных (название, ответы опросника, этапы с требованиями по
каждому, сводка трудозатрат «этапы / РП / риски / итого», риски), просто в разном формате:

- **PDF** (`GET /api/calculations/[id]/pdf`, `pdfkit`) — готовый к печати документ. Кириллица
  рендерится через встроенный шрифт DejaVu Sans (пакет `dejavu-fonts-ttf`), т.к. стандартные
  шрифты `pdfkit` поддерживают только латиницу.
- **XLSX** (`GET /api/calculations/[id]/xlsx`, пакет `xlsx`/SheetJS) — книга с листами
  «Расчёт», «Ответы», «Этапы» (включая колонку «Параллельно») и «Риски».
- **JSON** (`GET /api/calculations/[id]/json`) — тот же расчёт как структурированные данные,
  для интеграций и скриптовой обработки.

Общая логика загрузки и формирования имени файла вынесена в `lib/export.ts`.

## Тема оформления

Светлая тема — обычная, с точечными неоновыми розовыми акцентами (лого, фокус на полях ввода,
подсветка активной вкладки, свечение основной кнопки при наведении). Тёмная тема переключается
переключателем в шапке (сохраняется в `localStorage`, по умолчанию следует системной настройке)
и построена на палитре [Nord](https://www.nordtheme.com/), сдвинутой на один тон светлее стока:
карточки/панели/шапка — `nord2` (а не `nord1`), страница остаётся `nord0`.

Приглушённый текст (даты, подписи, заголовки таблиц) **не** использует стоковый `nord3` — при
проверке контраста (WCAG) он даёт всего ~1.2–1.7:1 против фонов `nord0–nord2`, то есть
практически не читается. Вместо него — кастомный тон `nord.muted` (`#b6c0ce`, ≥4.5:1 на любом
из этих фонов); `nord3` в тёмной теме используется только для рамок/разделителей. По той же
причине статус «Отклонён» использует `nord.redText` (`#e5a0a8`) вместо стокового `nord.red`,
который как текст даёт ~2.1–2.5:1. Точки контроля контраста — в комментариях
`tailwind.config.ts`.

## Запуск

```bash
cp .env.example .env
npm install
npm run db:push     # создаёт SQLite-схему
npm run db:seed     # демонстрационный шаблон, расчёт и пароли architect/admin
npm run dev
```

Приложение будет доступно на http://localhost:3000. Логины и пароли для входа в
`/architect` и `/admin` — см. вывод `npm run db:seed` или `credentials.local.txt`.
