# Предложения нормативов по факту

Часть #103, раздел 6 (WP-6c, пункт 6.4). Предложение изменить норматив этапа шаблона (`StageTemplate.baseHours` и `hoursPerUnit`) строится по факту завершённых проектов из журнала факта (`docs/actuals-ledger.md`) и вступает в силу только после утверждения владельцем шаблона.

Калибровка отдельного расчёта (`lib/calibration.ts`, панель «Калибровка») не меняется: она подсказывает поправку к одному расчёту и ничего не пишет в шаблон.

## Модель

`NormProposal` (миграция `20261031100000_norm_proposals`):

| Поле                                              | Назначение                                                                                    |
| ------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `stageTemplateId`, `formTemplateId`               | этап шаблона и шаблон                                                                         |
| `currentBaseHours`, `currentHoursPerUnit`         | снимок норматива при формировании                                                             |
| `proposedBaseHours`, `proposedHoursPerUnit`       | предлагаемый норматив                                                                         |
| `sampleSize`                                      | число полных наблюдений, вошедших в статистику (без выбросов)                                 |
| `completeness`                                    | доля завершённых этапов выборки, у которых внесён факт, 0..1                                  |
| `confidence`                                      | `low` / `medium` / `high`                                                                     |
| `explanation`                                     | метод, пороги, расчёты выборки (id, драйвер, формула, план, факт, коэффициент, учёт), выбросы |
| `fingerprint`                                     | отпечаток входных данных для идемпотентной перегенерации                                      |
| `status`                                          | `proposed` → `approved` / `rejected` / `superseded`                                           |
| `createdBy/At`, `decidedBy/At`, `decisionComment` | кто сформировал и кто решил                                                                   |

`CHECK` в БД повторяют потолки достоверности (см. ниже), частичный уникальный индекс `NormProposal_open_key` допускает одно открытое предложение на этап шаблона.

## Выборка

- Расчёты — **выигранные версии** шаблона (`Project.dealStatus = 'won'` и `wonCalculationId = id`): факт ведётся только по ним.
- Наблюдение — этап расчёта с тем же именем (без учёта регистра и лишних пробелов) и ролью, что этап шаблона; этапы согласования не участвуют. Если в шаблоне два этапа с одинаковыми именем и ролью, предложение по ним не строится.
- **Завершённый** этап — факт проекта закрыт (`Project.actualsClosedAt`) или у этапа внесена дата окончания факта. Незавершённые этапы в выборку не входят (частичный факт занизил бы норматив); их число показывается как «в работе».
- **Полное** наблюдение — у завершённого этапа есть часы факта (`Stage.actualHours`, агрегат журнала). **Нет факта ≠ 0 часов**: такие этапы не входят в статистику, а снижают полноту. Внесённые 0 ч — законное наблюдение.
- Наблюдение, для которого формула текущего норматива дала 0 ч, в статистику не входит (коэффициент не определён).

## Статистика

1. Для каждого полного наблюдения — коэффициент `факт / формула`, где формула — `baseHours + hoursPerUnit × драйвер` по **текущему** нормативу и ответам расчёта. Так предложение — поправка именно к действующему нормативу, даже если расчёт создан по старому.
2. От 4 полных наблюдений отсекаются выбросы по Тьюки: вне `[Q1 − 1.5·IQR; Q3 + 1.5·IQR]`. Они видны в объяснении со статусом «выброс».
3. Коэффициент — медиана оставшихся.
4. Предложение = текущий норматив × коэффициент (база округляется до 0.1 ч, часы на единицу — до 0.01 ч). Изменение меньше 5% не предлагается.

План (`Stage.hours`, мог быть исправлен архитектором) показывается рядом для сравнения, но в коэффициент не входит.

## Достоверность

| Условие                                                                      | Уровень       |
| ---------------------------------------------------------------------------- | ------------- |
| полных наблюдений меньше 3 (`MIN_NEIGHBOURS` калибровки)                     | не выше `low` |
| полнота ниже 70%                                                             | не выше `low` |
| не меньше 8 полных наблюдений, полнота от 90%, разброс (IQR / медиана) ≤ 50% | `high`        |
| иначе                                                                        | `medium`      |

Малой или неполной выборке высокая (и даже средняя) достоверность не приписывается; причины уровня перечислены в `explanation.confidenceReasons`.

## Генерация и перегенерация

`POST /api/templates/:id/norm-proposals` (только `admin`) пересчитывает предложения всех этапов шаблона под advisory-блокировкой шаблона:

- открытое предложение с тем же отпечатком остаётся без изменений — повторный запуск без новых данных ничего не создаёт;
- иначе прежнее открытое предложение становится `superseded`, создаётся новое;
- открытые предложения этапов, по которым предложения больше нет (данных не хватает, факт совпал с нормативом), тоже становятся `superseded`.

`GET` того же адреса — список (последние сначала). Аудит: `template.norms.generate`.

## Утверждение

`POST /api/templates/:id/norm-proposals/:proposalId` с `{ decision: 'approve' | 'reject', comment }`, только `admin` — владелец шаблонов:

- **approve** записывает предложенный норматив в `StageTemplate`. Действует для новых расчётов: этапы существующих расчётов — копии и не пересчитываются. Если норматив изменили после формирования предложения, ответ 409 — предложение нужно сформировать заново;
- **reject** требует комментария и шаблон не меняет;
- решение по закрытому предложению — 409.

Аудит: `template.norms.approve` / `template.norms.reject` с нормативом до и после.

## Экран

Редактор шаблона (`/admin/:id`), блок «Предложения нормативов по факту»: пересчёт, открытые предложения с достоверностью и причинами её уровня, таблица выборки (расчёт, драйвер, формула, план, факт, коэффициент, учёт), утверждение/отклонение с комментарием, история решений.
