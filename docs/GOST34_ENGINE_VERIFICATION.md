# Проверка движка ГОСТ ТЗ

База проверки: `db9ee4cd7e7417496db012e8b21035beafb044af` (`main`).
Область: схема ТЗ 34.602-2020, совместимость legacy-89, ручные и LLM-правки,
предпросмотр, DOCX, входные реквизиты и источники требований.

## Исправленные дефекты

| Дефект | Изменение |
| --- | --- |
| Пустой обязательный раздел после ручной правки экспортировался с пустой диагностикой | Проверка итогового дерева после overrides; preview возвращает issues, экспорт отвечает 409 |
| Проверка структуры не замечала порядок подразделов и пропущенные вложенные узлы | Рекурсивный валидатор `schema/coverage.ts`; проверка пустых заголовков и содержимого |
| Неизвестный docType молча превращался в ТЗ, сохраняя неправильные метаданные | Явная ошибка 400, в том числе для ключей прототипа JavaScript |
| Кириллическое имя файла ломало прямой HTTP-download | Общий `Content-Disposition` с UTF-8 filename* |
| Генератор и UI подставляли демонстрационные ФИО, договор, инвентарный номер и дату подписи | Общие пустые реквизиты; явные значения сохраняются, дата генерации не выдаётся за дату подписи |
| NGFW/КИИ-пресеты придумывали обработку ПДн, класс защиты и regulatoryScope | Удалена эта эвристика; учитываются явные ответы и ручной контекст |
| Отсутствовали сведения об источниках и порядке финансирования | `ProjectContext.funding`, provenance/gap, раздел «Общие сведения» и grounding LLM |
| Заголовки третьего уровня получали Heading2 | Heading3 для вложенных заголовков |
| Таблицы приложения Б продолжали счётчик приложения А | Отдельный счётчик каждого приложения |
| Предпросмотр терял реквизиты, параметры обогащения и список файлов | Единая подготовка AST и передача этих полей через UI/API; файлы и tzAuthor сохраняются в снимке |
| GET-релиз записывал любой вид документа как tz | В реестр передаётся фактический docType и actorId |

Последние изменения не переписывают ранее сохранённые снимки: уже сохранённые
пользовательские значения сохраняются, включая старые демонстрационные реквизиты.

## Нормативная сверка

Схема сохраняет десять обязательных разделов и их порядок. Сверены п. 4.1, 4.3
и 5.1 ГОСТ 34.602-2020 по [копии официального издания](https://www.swrit.ru/doc/gost34/34.602-2020.pdf).
В п. 4.3 обнаружен пропуск финансирования. Если данных нет, теперь появляется
явный пробел, а не выдуманный источник средств. Эталоны обновлены только для
добавленного абзаца и gap `funding`; структура legacy-документа сохранена.
Это ограниченная проверка реализации выбранного профиля, а не подтверждение
актуальности всех отраслевых НПА в каталоге или полного нормативного соответствия ТЗ.

## Разделение модулей

- `generation/prepareDocument.ts`: нормализация, baseline, LLM-проверка,
  наложение правок, итоговая диагностика. Общий путь preview/export.
- `generation/exportDocument.ts`: упаковка подготовленного AST в DOCX.
- `generation/overrides.ts`: чистая обработка правок. Внутренние LLM-модули
  импортируют её напрямую, без обратной зависимости на публичный barrel.
- `generation/errors.ts`, `generation/apiError.ts`: доменные ошибки и HTTP-адаптер.
- `schema/coverage.ts`: проверка дерева независимо от рендерера.
- `exporters/titlePage.ts`, `documentBody.ts`, `typography.ts`: титульный лист,
  содержимое и типографика. `docxExporter.ts` сократился с 469 до 167 строк
  и отвечает за сборку страниц, колонтитулов, стилей и упаковку.
- `lib/exportResponse.ts`: HTTP-заголовки и тело ответа без подключения Prisma.

## Проверки

Воспроизводимый независимый прогон:

```sh
npm run test:gost34:verify
npm test -- lib/gost34
npm run typecheck
npm run lint
```

`test:gost34:verify` проверяет реальные AST и DOCX без БД и внешней LLM:

- девять golden-сценариев;
- равенство AST preview/export в трёх layout-профилях (27 документов);
- девять типов документов × два нормативных профиля × три layout (54 документа);
- один специальный документ с вложенными заголовками и двумя приложениями;
- 139 проверок, включая ZIP/XML, обязательные разделы, LLM gate, реквизиты,
  кириллический HTTP-заголовок, происхождение security-полей и финансирование.

В рабочей среде этот прогон выполнен через доступный Babel TypeScript-loader:
**139 проверок, 82 DOCX — PASS**. Исходные дефекты пустого раздела, неизвестного
docType, кириллического заголовка, реквизитов и security-подстановки отдельно
воспроизведены на базовом коммите.

Ограничения среды: npm и GitHub git-endpoint недоступны; исходники получены
через GitHub connector. Использован доступный `docx 9.6.1`, тогда как проект
объявляет `^9.7.1`. Полные Vitest, typecheck, lint, Next build и Jenkins здесь
не запускались. Новые Vitest-регрессии добавлены для штатного CI. Проверка
синтаксиса изменённых TS/TSX выполнена Babel; она не заменяет проверку типов.
Пагинация и внешний вид в Microsoft Word/LibreOffice не проверялись.

## Оставшиеся ограничения

1. `context/builder.ts` по-прежнему содержит отраслевые предположения о вендорах
   и SLA 99.9%. Следующий этап — отделить предложения пресетов от подтверждённых
   параметров, с явным решением пользователя перед включением в ТЗ.
2. Наличие всех разделов не доказывает полноту их содержания: ручная правка может
   заменить обязательный текст любым непустым абзацем. Gaps и замечания мастера
   остаются обязательной частью содержательного согласования.
3. Структурный gate проверяет профиль 2020; для legacy-89 сохранена совместимость,
   а отдельная рекурсивная нормативная схема legacy в этот PR не добавлялась.
4. Snapshot хранит решения мастера, но воспроизводимость всего комплекта требует
   также неизменяемой версии расчёта и версий внешних исходных документов.
5. ZIP по-прежнему держит документы в памяти и повторяет подготовку для каждого
   типа. Оптимизацию общего контекста следует делать после измерения крупных
   комплектов; в этой проверке ускорение или снижение памяти не заявляется.
