# Производственные календари и резервы ролей

Часть #103, раздел 5 «Ресурсное планирование», пункт 5.1.

## Зачем

До этого Гант и ресурсный план по-разному понимали рабочие дни: `lib/scheduling.ts`
определял выходные по локальному часовому поясу сервера (`getDay()`), а
`lib/capacity.ts` — по UTC (`getUTCDay()`). На сервере с TZ ≠ UTC этап на границе
суток попадал в разные дни, и Гант с портфельным планом расходились. Праздников и
резервов не было вовсе.

## Модель

| Модель              | Назначение                                                                                                                                              |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `WorkCalendar`      | Название, выходные дни недели (`weekendDays`, ISO 1 = пн … 7 = вс, по умолчанию `6,7`), признак `isDefault`. Основной календарь ровно один.             |
| `CalendarException` | Дата календаря и тип: `holiday` (нерабочий), `workday` (рабочий выходной, перенос), `short` (сокращённый, `hours` из 8, по умолчанию 7 — ТК РФ ст. 95). |
| `RoleReservation`   | Роль, период `[from, to]`, часов в неделю, причина, автор. Вычитается из ёмкости роли.                                                                  |
| `FormTemplate`      | `calendarId` — календарь шаблона; `null` — основной календарь.                                                                                          |

Миграция `20261015100000_work_calendars` создаёт таблицы с CHECK-ограничениями
(тип исключения, часы только у сокращённого дня, `to ≥ from`, не все семь дней
выходные) и частичный уникальный индекс «один основной календарь», а также
сам основной календарь «Основной (пн–пт)» без праздников. Праздники конкретного
года в миграцию не зашиты — их вносит администратор, например списком:

```text
2027-01-01 праздник Новый год
2027-02-22 короткий 7
2027-11-06 рабочий перенос
```

## Расчёт

Общий модуль — `lib/calendar.ts`, только UTC. Каждый день получает долю рабочего
дня `dayFactor`: 0 — выходной или праздник, 1 — обычный или рабочий выходной,
`hours / 8` — сокращённый. Праздник сильнее флага шаблона «учитывать выходные».

- **Гант** (`lib/scheduling.ts`): рабочее окно дня 09:00 UTC + `workDayHours × dayFactor`.
  Праздник пропускается, сокращённый день вмещает меньше часов, рабочий выходной
  используется. SLA согласования считает только дни с ненулевой долей.
- **Ресурсный план** (`lib/capacity.ts`): часы этапа раскладываются по дням
  пропорционально `dayFactor` того же календаря, по которому строился Гант
  (календарь шаблона расчёта, иначе основной). Поэтому для этапа, начатого с
  утра и кратного рабочему дню, часы плана по дням совпадают с Гантом.
- **Ёмкость роли** = ставки × часов в неделю × (сумма долей недели / число рабочих
  дней обычной недели) − резервы. Резерв масштабируется так же: праздник внутри
  периода резерва уменьшает и его. Ячейка плана показывает вычтенный резерв.

Без исключений и резервов результат совпадает с прежним (кроме исправленного
часового пояса: начало дня теперь всегда 09:00 UTC).

> **При обновлении.** Перестроенные Ганты (после правки этапов или даты старта)
> используют рабочее окно с 09:00 UTC. На серверах с `TZ` ≠ UTC раньше окно
> начиналось в 09:00 местного времени, поэтому даты перестроенных Гантов
> сдвинутся относительно сохранённых ранее (в Москве — на 3 часа позже,
> иногда на следующий день). Уже сохранённые даты этапов не переписываются.

## Интерфейс и API

- `/admin/calendars` (только admin): календари, выходные дни недели, исключения
  по одной дате и списком, резервы ролей. В шаблоне (`/admin/:id`, блок
  «Рабочий график») выбирается календарь.
- `GET/POST /api/admin/calendars`, `PATCH/DELETE /api/admin/calendars/:id`,
  `POST/DELETE /api/admin/calendars/:id/exceptions`, `GET/POST/DELETE /api/admin/reservations`.
  Запись — только admin, чтение — планирующие роли. Основной календарь нельзя
  удалить или разжаловать: можно только назначить основным другой.

## Ограничения

- Уже построенные Ганты хранят даты этапов; после правки календаря они
  пересчитываются при следующем изменении этапов или даты старта расчёта
  (утверждённые расчёты не перестраиваются). Ресурсный план перераспределяет
  часы по новому календарю сразу.
- Применение what-if (`/api/capacity/apply`) сдвигает даты этапов на целые дни
  без перестройки Ганта и календарь не учитывает.
